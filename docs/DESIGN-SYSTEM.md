# 康复助手设计系统

本文件是 UI（User Interface，用户界面）和 UX（User Experience，用户体验）的组件与行为标准。产品硬约定仍以 [AGENTS.md](../AGENTS.md) 为准；代码实现方法见 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 1. 设计目标

患者能知道「现在在哪里、下一步做什么、有没有保存、怎样回去」。家属能核对记录和迁移数据。每个任务保留明确出口，不通过评分、复杂比率或催促制造压力。

## 2. 基础变量

颜色和尺寸的值只在 [css/style.css](../css/style.css) 维护，本表说明语义；[组件样张](design-system.html) 直接引用应用样式，可双击查看。

| 变量 | 用途 |
|---|---|
| `--bg` / `--card` / `--surface-subtle` / `--surface-hover` | 页面中性背景 / 信息表面 / 控件底色 / 鼠标悬停与按下 |
| `--text` / `--text-2` | 结论与正文 / 补充解释，次级文字仍需可读 |
| `--primary` / `--primary-dark` / `--primary-soft` | 主操作 / 浅色底上的操作文字 / 行内操作底色 |
| `--green` / `--green-soft` | 已完成；搭配勾号或文字 |
| `--orange` / `--orange-soft` | 提醒、可重试；搭配原因和办法 |
| `--red` / `--red-soft` | 急救、错误、破坏性操作；不用于训练成绩 |
| `--space-1/2/3/4/6/8` | 从细间隔、控件间隔到段落与宽屏留白 |
| `--radius-control/sheet` / `--radius` | 控件 / 弹窗 / 卡片圆角 |
| `--content-width` / `--touch-target` | 内容宽度上限 / 最小触控目标 |
| `--shadow` / `--shadow-overlay` | 轻微表面层次 / 独立任务浮层 |

正文维持三档字号；说明文字不靠浅灰和透明度隐藏。普通文字与背景至少 4.5:1，对状态颜色、实心按钮反白字同样检查。布局在 320、360、390、768、1024、1280px 与三档字号组合下无横向滚动；长标签整体换行，不能截断急救或保存操作。动效服从系统「减少动画」。

手机保留五项底部导航；1024px 起使用左侧导航与右侧内容，仍是同一份 DOM（文档对象模型，页面的实际元素），改窗口大小不会丢表单输入。380px 及以下的任务／训练列表把按钮放到文字下方，不能将名称挤成窄列来满足「无溢出」。平板与桌面弹窗居中，手机使用底部面板；底部留出系统安全区。今日问候与其他页标题保持同一层级，避免大面积强调色盖过任务。只有真实可点击的行才给整行悬停反馈；触屏不依赖悬停提示。

## 3. 组件契约

| 组件 | 使用方式 | 必备状态 |
|---|---|---|
| `.section-label` + `.list-group` / `.action-list` | 同类内容一卡多行；标题是扫读锚点 | 空态要给出下一步 |
| `.btn` | 当前任务的主操作；标签用「保存设置」「确认恢复」等具体动词 | 默认、按下、键盘焦点、处理中 |
| `.btn.ghost` / `.btn.outline` | 行内操作 / 次要操作 | 不因层级下降缩小触控面积 |
| `segGroupHTML` + `bindSegGroup` | 字号、语速等即时偏好 | 从 Store 派生选中态；写入失败恢复原选择 |
| `.notice` / `.save-feedback` | 持续说明 / 保存失败与处理办法 | 文字说明，错误可被读屏播报，保留输入 |
| `toast` | 已完成的短反馈 | 约五秒；关键错误不能仅放在这里 |
| `openModal` / 训练页 | 独立任务容器 | 标题、关闭、急救、焦点边界、返回焦点 |
| `.call-120` | 急救卡首屏唯一主操作 | 直接 `tel:120`，号码可见，无法唤起时有手拨说明 |

设置中的表单字段用真实 `label` 关联输入。图表同时给文字结论；颜色不单独承载完成、危险或选中状态。主导航以 `aria-current` 标记当前位置。列表中的「开始」「修改」按钮向读屏提供动作名或药名，避免连续听到含义不明的同名按钮。

## 4. 导航与返回

| 场景 | 打开 | 完成／关闭 |
|---|---|---|
| 设置 → 使用指引／音色帮助／健康报告 | 子弹窗，保留父窗口 DOM 与草稿 | 回到原设置位置，再关闭设置回原页 |
| 设置 → 备份 | 子任务 | 下载发起或取消后回设置 |
| 备份 → 加密；解密 → 恢复预览 | 同一任务，`close.replace()` | 返回一次退出该任务，无额外中间历史 |
| 首次指引 | 覆盖当前深链接页 | 关闭后留在该页，不强制跳「今日」 |
| 训练 → 急救 | 急救覆盖训练；计时暂停，朗读停止 | 回原训练，计时由用户主动继续 |
| 数据保存后的重渲染 | 保留主页面滚动位置 | 设置保存同时保留底下记录表单的输入 |

✕、Esc、返回键、遮罩点击语义相同，一次只关顶层。焦点先到弹窗标题，Tab 留在顶层；底下内容不可点，页面不可随手势滚动。关闭后焦点回触发按钮且不自动滚屏；保存重建了列表时，按条目标识返回新节点。只有主动切换主导航才回页首；刷新按当前 `?view=` 打开。

## 5. 数据任务与反馈

1. 表单先完成校验再改 Store。失败保留输入，给出原因和修正办法；成功写盘后才显示成功并关闭。
2. 导出健康报告用于阅读，完整备份用于恢复，两者标签不能混淆。下载只能提示「已发起」，用户仍需在下载列表或文件管理器确认。
3. 恢复顺序是选文件 → 校验／可选解密 → 查看条数和覆盖说明 → 确认 → 建立恢复点 → 写入。取消和校验失败不改数据；恢复成功后设置从新数据重建，避免旧草稿覆盖恢复结果。
4. 加解密期间防重复执行；用户关闭后任务结果不能触发下载或再弹窗口。同一备份可以重新选择。密码不保存。
5. 本地数据损坏或读取失败时显式提示并阻止日常写入；原始内容保留。损坏副本可下载供排查，但不得称为已验证的备份。容量超限拒绝保存，不能截掉记录后显示成功。
6. 保存前检测其他页面是否已更新数据，发现变化就拒绝覆盖并提示重新打开。此检测不是跨进程事务锁；日常只保留一个编辑页面。未来若必须支持同时编辑，需要另行设计存储事务。

## 6. 急救与医学边界

急救不依赖填写设置、保存成功、解密或完整读完识别列表。主界面、弹窗标题栏与训练页都能进入；卡片先显示拨号，再显示既有识别与处置说明。医学文本与来源仍由 [RESEARCH.md](RESEARCH.md) 管理。应用不能确认电话是否接通，不能替代急救服务。

## 7. 维护与验收

新增交互先选上表中的场景，再复用组件，避免每个页面另写返回逻辑。调整基础变量后看组件样张并检查应用真实页面。自动化入口见 [DEVELOPMENT.md §7](DEVELOPMENT.md#7-测试)，手工步骤只维护在 [MANUAL-TEST.md](MANUAL-TEST.md)。测试应验证行为与可恢复数据，不以选择器存在代替用户路径。

## 8. 参考与分阶段加固

参考 [Linear 官方界面重设计说明](https://linear.app/now/how-we-redesigned-the-linear-ui)：减少视觉噪音、对齐导航与内容、用表面与对比建立层次，并在真实页面及状态中检查。采用其一致性与验证方法；本项目的密度、字号与操作尺寸以患者可读、可点为准。

| 阶段 | 交付与验收门槛 |
|---|---|
| 视觉基础 | 语义颜色、间距、控件、响应式外壳共用一套样式；六种宽度与三档字号检查布局、对比度和触控尺寸 |
| 任务稳定性 | 打卡、修改、失败重试、嵌套返回与跨宽度切换保留正确状态；压力回归不能增加无用历史或重复下载 |
| 真机验收 | 按现有真机清单核对原生返回、键盘、读屏、朗读和下载落地；未通过的路径修复后再验，不能用浏览器模拟替代 |
